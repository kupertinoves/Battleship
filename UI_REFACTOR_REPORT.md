# UI Refactor Report

Дата аудита и выполнения: 28.10.2026.

## Обновление после отката NGO

Через Unity MCP из Game удалены связанные с NGO Host/Join и общая пауза, их контроллеры и кнопочные вызовы. Редакторское оформление полей, заголовков и легенды сохранено. Исходный GameWsClient подключён к готовому `Canvas/Root/status`; исходный URL и `GameUIController.ws` восстановлены в Inspector. Tutorial, BotGame и остальные UI-доработки сохранены. Windows x64 сборка прошла: 13 сцен, 0 ошибок, 0 предупреждений. Приведённые ниже описания NGO-панели/паузы относятся к истории до отката.

## Исходное состояние

В проекте найдена runtime-генерация постоянного UI в `UIRuntimePolish.cs` и связанных `NavalScreenLayouts.cs`, `NavalConnectionLayout.cs`, `NavalPauseLayout.cs`: создаются панели/элементы экранов и задаются визуальные размеры, координаты и оформление из C#. `GameCellView.cs` также создавал Image, Button и TMP-маркер при инициализации, а `CellView.cs` зависел от runtime-polish стилей. Это усложняло редактирование экранов и проверку ссылок через Inspector.

## Выполнено

- Для `GameCellView` удалено создание постоянных компонентов и дочернего TMP-текста в коде. Компоненты Image и TMP теперь сериализованы и назначены на компоненты существующего `GameCellPrefab` через Unity MCP. Цветовые поля клетки доступны в Inspector.
- Из `CellView` удалена привязка стиля к `UIRuntimePolish`; цвета расстановочной клетки вынесены в сериализованные настройки.
- Через Unity MCP создана отдельная сцена `Assets/Scenes/BotGame.unity`: Canvas, CanvasScaler, фон, заголовки, поля с GridLayoutGroup, текст состояния, кнопки, EventSystem и `BotGameUIController`. Все визуальные элементы находятся в сцене; повторяющиеся 100 клеток создаются из назначенного префаба `GameCellPrefab`.
- Через Unity MCP добавлена в MainMenu кнопка «ИГРА С БОТОМ», которая использует editor-authored `SceneLoadButton` и загружает `BotGame`.
- Через Unity MCP создана сцена `Tutorial` с Canvas, TMP-текстами, тремя кнопками и `PracticeGrid` на базе `GameCellPrefab`; постоянная структура интерфейса находится в сцене, а не в кодовой генерации.
- MainMenu дополнен editor-authored заголовком и кнопками «ОБУЧЕНИЕ»/«ВЫХОД». Для обучения и выхода подключены отдельные сериализуемые контроллеры.
- MainMenu и Settings используют постоянные редакторские панели; старые неработающие `Chat`/`GameFon` и `Fone` скрыты, но не удалены.
- Исправлена кнопка Settings в MainMenu: оставлен существующий сценовый UnityEvent. Проверены переходы MainMenu → Settings → MainMenu; дублирующий `SceneLoadButton` удалён после аудита.
- Auth и Registration содержат статические редакторские панели, заголовки, подписи, поля, кнопки и error text. Сохранены существующие контроллеры и UnityEvent-ссылки; парольные поля используют `TMP_InputField.ContentType.Password`.
- Удалены runtime-генераторы форм Auth/Registration, старого MainMenu и Settings из `UIRuntimePolish.cs`/`NavalScreenLayouts.cs`; соответствующие экраны исключены из runtime-позиционирования.
- `ShipsAssigment` переработана через Unity Editor: статические карточка флота, подписи кораблей, счётчики палуб, координатные оси, прогресс и кнопки сохранены в сцене; `PlacementScreen.feedbackText` подключён. Runtime-позиционирование и генерация feedback для этой сцены удалены; 100 игровых клеток по-прежнему появляются из prefab.
- `Statistic` показывает локальные итоги в статической карточке сцены. Добавлен `LocalStatisticsPanel` с Inspector-ссылками на готовые TMP-тексты и пустое состояние; он не создаёт GameObject. Рейтинг подключён к существующему `RatingService`: `RatingPage` показывает статусы загрузки/ошибки/отсутствия данных и создаёт строки только из готового `PlayerRow` префаба. В Canvas через Unity MCP добавлен `RatingStatus`; `RatingService` и формат API не менялись. Без токена запрос не отправлялся, реальные строки рейтинга не проверены.
- Повторный поиск по сценам/префабам/скриптам нашёл только неиспользуемый `PixelAlignedFleetGrid` с расчётом размеров сетки и координат подписей. Ссылок на него нет; класс оставлен для совместимости, но теперь не выполняет раскладку. Оставшиеся операции позиционирования в C# по этому поиску отсутствуют.
- Unity MCP просканировал сериализованные поля всех пользовательских компонентов во всех 14 сценах: пустых объектных ссылок не осталось. В процессе были заполнены `SceneLoadButton.button` для Settings и `PlacementScreen.feedbackText` у кнопки Ready. Затем у Settings удалён лишний `SceneLoadButton`: исходный UnityEvent уже выполнял переход и оставлен единственным, чтобы не запускать повторную загрузку сцены.
- В `ToggleButtonColor` цвета перехода больше не заданы `Color.green`/`Color.red` в C#: добавлены два Inspector-поля и сохранены эквивалентные зелёный/красный цвета в компоненте сцены Settings.
- `Account` получил статическую профильную панель, редакторские строки Login/Email и оформленные кнопки. Существующие значения `Login`/`Email`, `GetUserInfo` и события кнопок сохранены; Play Mode не запускался, чтобы не вызывать загрузку профиля через API.
- `Game` теперь содержит редакторские панели двух полей, заголовки, статус, легенду и отдельные overlay подключения и паузы. Для повторяющихся 100 клеток каждого поля по-прежнему используется prefab. `ConnectionMenuUI` связывает элементы сцены с существующими методами/событиями клиента, `BattlePauseController` использует уже имеющееся состояние подключения. `NavalConnectionLayout` больше не создаёт экран, генерация `NavalPauseLayout` удалена, экранный layout Game удалён из `NavalScreenLayouts`.
- `UIRuntimePolish` больше не создаёт или оформляет UI: он только записывает локальный исход матча при загрузке WIn/Defeat. `NavalScreenLayouts` удалён; оставшиеся layout-скрипты не строят экранов. Поиск подтвердил, что сценарные Image/Button/Text компоненты не создаются в рантайме. Клетки инстанцируются из подготовленных префабов, а сетевой клиент создаёт только NetworkManager.
- `WIn` и `Defeat` получили сохранённые в сценах карточки, заголовки, пояснения и кнопки меню. `Change_scene` и кнопочные события сохранены.
- `ChangePassword` получила сценовую карточку формы, морские кнопки, контрастные поля, русские подсказки и `Password` content type.
- `Tutorial` дополнительно оформлена в Editor: полноэкранный фон, карточка, заголовок, счётчик шага, текст, поле упражнения, обратная связь и кнопки; Game View при 1280×720 читаем.
- Исходная tracked-сцена `New Scene.unity` сохранена со своим прежним GUID; новая сцена `BotGame` имеет отдельный GUID.

## Осталось

- Полный онлайн-сценарий Game после подключения к реальному серверу не проходил.
- В Play Mode подтверждены фактические `Screen.width/height` и проверены визуальные кадры для Tutorial, BotGame, MainMenu, Auth, Registration, ShipsAssigment, Game, Statistic, Settings, WIn, Defeat и ChangePassword при 1280×720, 1366×768, 1600×900, 1920×1080 и 2560×1440. Game проверена без запуска Host/Join, формы и API не отправлялись. Account в Play Mode не запускался, поскольку его `Start` инициирует получение профиля/переход при отсутствии токена. Сериализованные object references и persistent UnityEvent-слушатели проверены отдельно через Unity MCP.
- Для `BotGame` сетка создаётся из подготовленного prefab. Через Unity Editor Play Mode реальным вводом проверены допустимая расстановка, полный матч до поражения, повторная игра и полный матч до победы. В EXE проверены расстановка, выстрел, попадание и ответ бота, но матч до результата в Player не завершён. Game View на фактических `Screen.width/height` проверен для Tutorial, BotGame, MainMenu, Auth, Registration, ShipsAssigment, Game, Statistic, Settings, WIn, Defeat и ChangePassword на всех пяти целевых разрешениях. Account Play Mode и онлайн/API-сценарии не запускались.

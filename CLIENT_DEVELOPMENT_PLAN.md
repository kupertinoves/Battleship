## Исходное состояние

Аудит выполнен 28.10.2026 в рабочем Unity Editor через Unity MCP и по текущему дереву Git. Открытый проект — `Battleship`; сцены проверялись через MCP Hierarchy. В Build Settings уже включены MainMenu, Auth, Registration, Account, ShipsAssigment, Game, Statistic, Settings, Defeat, WIn и ChangePassword.

На момент начала работы рабочее дерево уже было изменено: `git status --short --branch` показывал изменения в сцене Game, игровом UI-контроллере, сетевых/игровых и расстановочных скриптах, статистике, TMP-ресурсе, пакетах и настройках проекта, а также удаление `Assets/Scripts/Game/WsClient.cs` и `.meta` и ряд новых неотслеживаемых файлов. Эти изменения не были созданы этой работой. Сетевые, API, конфигурационные и ранее изменённые файлы сохраняются без отката и без дополнительного вмешательства.

## Реализовано на момент аудита

- Есть основные сцены авторизации, регистрации, профиля, расстановки, игры, статистики, настроек и исходов матча.
- В Game существуют поля игрока и противника на `GameGridView`, TMP-индикатор статуса и UI-контроллер.
- В сцене расстановки есть GridController, кнопка готовности и PlacementScreen.
- В Statistic есть ScrollRect с Content и RatingService/RatingPage.
- Build Settings содержат перечисленные выше рабочие сцены; `New Scene` присутствует в проекте, но не включена.
- В Assets есть префабы клеток и строки рейтинга.
- Добавлена отдельная сцена `BotGame` с редакторской Hierarchy, Canvas Scaler (1920×1080, Scale With Screen Size), двумя GridLayoutGroup-полями, кнопками и привязками контроллера. Сцена добавлена в Windows Build Settings; исходный `New Scene.unity` сохранён.
- Добавлена сцена `Tutorial` с 10 шагами, двумя интерактивными упражнениями, кнопками и сеткой из клеточного префаба. В MainMenu добавлены ссылки на обучение и выход.
- Tutorial дополнена упражнением на уничтожение двухпалубного корабля; теперь четыре практических задания. Уточнены правила касания и локальной очередности. В BotGame готовые кнопки блокируются по состоянию матча; новые объекты UI не создавались.
- Постоянная раскладка MainMenu теперь хранится в сцене: созданные ранее в рантайме заголовок/HelpButton/MenuCard заменены редакторскими объектами, а `OnSceneLoaded` больше не генерирует элементы и не перепозиционирует MainMenu.
- В Settings создана постоянная редакторская панель с громкостью, переключателями звука и полного экрана, сбросом и возвратом. `SettingsController` сохраняет параметры локально через PlayerPrefs. В MainMenu включена и подключена кнопка настроек.
- Auth и Registration переведены на статические элементы Hierarchy; поля пароля используют `Password` content type. Удалены старые runtime-layout методы MainMenu, Settings, Auth и Registration.
- Сцена `ShipsAssigment` получила статическую Canvas-раскладку поля и флота, координатную разметку, прогресс и морские стили кнопок; обратная связь назначена в Inspector. Runtime-layout для этой сцены отключён.
- `Statistic` показывает локальные итоги в статической карточке и использует существующий `RatingService` для списка рейтинга через префаб `PlayerRow`; в сцене добавлен редактируемый `RatingStatus` для загрузки, пустого состояния, отсутствия токена и ошибки API. Контракт `RatingService` не менялся. Во время проверки токена не было, поэтому запрос рейтинга не отправлялся.
- Повторный поиск по `Assets` выявил неиспользуемый `PixelAlignedFleetGrid`, который вычислял размеры сетки и позиции координатных подписей в `LateUpdate`. По ссылкам сцен и префабов он нигде не назначен; класс сохранён для совместимости, но превращён в пустой компонент, а раскладка остаётся в Unity Editor.
- Жёстко заданные зелёный/красный цвета в старом `ToggleButtonColor` перенесены в сериализованные поля `selectedColor`/`unselectedColor`, выставленные через Inspector в Settings. Повторный статический поиск UI-размеров, координат, цветов и runtime-создания стандартных UI-компонентов не нашёл активного построения UI; остаётся только сетевой `NetworkManager` в `GameNgoClient`.
- Unity MCP повторно проверил сериализованные поля пользовательских компонентов во всех 14 сценах (включая не включённую в сборку `New Scene`): пустых ссылок нет. В MainMenu назначение Settings оставлено на существующем UnityEvent; в ShipsAssigment текст обратной связи назначен второму `PlacementScreen` на кнопке Ready.

## Обнаруженные проблемы и ограничения

- Runtime-оформление `UIRuntimePolish` удалено; `NavalScreenLayouts` удалён, `NavalPauseLayout` больше не генерирует панель. `NavalConnectionLayout` связывает статический UI с существующим клиентом. Остались только `Instantiate` подготовленных клеточных префабов и создание сетевого NetworkManager существующим клиентом.
- `GameCellView` использует сериализованные ссылки на Image/TMP, назначенные в prefab; он не создаёт визуальные компоненты.
- Профиль получил статическую раскладку сцены; проверены Inspector-ссылки существующего `GetUserInfo`. Его Play Mode не запускался, чтобы не инициировать API-запрос. Онлайн-сценарий с сервером не проходил. Account и фактические API-ответы рейтинга остаются непроверенными.
- На пяти размерах 1280×720, 1366×768, 1600×900, 1920×1080 и 2560×1440 в Play Mode проверены Tutorial, BotGame, MainMenu, Auth, Registration, ShipsAssigment, Game, Statistic, Settings, WIn, Defeat и ChangePassword; Game проверялась без Host/Join, API формы не отправлялись. Все 10 шагов Tutorial и три упражнения пройдены в EXE. В Unity Editor завершены обе ветки локальной игры; полный матч в EXE до результата не доведён.
- В момент аудита на диске нет плана проекта, README или критериев MVP; фактический план не найден.
- Повторный снимок Hierarchy через Unity MCP в этой работе охватил Account, Auth, Registration, ShipsAssigment, Game, Statistic, Settings, Defeat, WIn и ChangePassword; у проверенных сцен есть Canvas, в снимках нет компонентов `Missing Script`.
- Рабочее дерево до начала этой работы уже содержало удалённый защищённый `WsClient.cs`/`.meta`, существенно изменённый `GameUIController.cs`, `GameNgoClient.cs` и изменение пакетов: NativeWebSocket удалён, добавлены Netcode for GameObjects и Unity Transport. Сцена Game использует NGO-клиент. Это прямо конфликтует с требованием сохранять WebSocket; конфликт существовал до этой работы и не изменялся. Поэтому онлайн-критерий сохранения сетевой архитектуры сейчас не выполнен.
- Текущий `RatingPage` теперь вызывает существующий `RatingService` и создаёт только строки из готового префаба. Запрос API и ответы сервера не проверялись из-за отсутствия токена.
- Добавлены пять Unity EditMode-тестов локальной модели. Unity Test Runner обнаружил тестовый набор и подтвердил `5/5`; первый прогон выявил зацикливание в тестовом поиске клетки, helper исправлен перед успешным повторным запуском.
- Наличие сцен в редакторе само по себе не доказывает корректную привязку всех UnityEvent/Inspector-ссылок и не подтверждает сетевой сценарий с сервером.

## План с приоритетами

1. **P0 — Безопасность изменений:** сохранить исходные незакоммиченные изменения; исключить backend, API, WebSocket/NGO, авторизацию/токены и конфигурацию сервера из правок.
2. **P0 — T01/T19 UI-аудит и рефакторинг:** постоянная UI-генерация и runtime-стили удалены из клиентских layout-скриптов; сериализованные объектные ссылки проверены во всех сценах. Продолжить визуальную приёмку и пользовательские smoke-тесты оставшихся экранов.
3. **P1 — Проверка игровых сцен:** сверить Hierarchy/Inspector/Game View, ссылки и переходы в доступных сценах через Unity MCP.
4. **P1 — Локальное обучение и матч с ботом:** обучение пройдено в EXE с реальным вводом; правила и 10 полных симуляций проверены; через UI Unity Editor реальным вводом завершены поражение, повторная игра и победа. Полный матч в собранном EXE остаётся для отдельной ручной проверки.
5. **P1 — Клиентский UX:** привести меню, расстановку, матч, результаты, настройки, профиль и рейтинг к общему морскому стилю; не подменять серверные данные.
6. **P2 — Адаптивность и полировка:** Canvas Scaler/anchors/layout, визуальные состояния и умеренные анимации.
7. **P2 — Проверки и сборка:** компиляция, пять EditMode-тестов, Windows x64 сборка и матрица пяти разрешений для всех проверяемых сцен завершены; полный тест онлайн-матча и профиль/рейтинговый API недоступны без авторизованного сервера.
8. **P2 — Документация:** поддерживать UI_REFACTOR_REPORT.md и CLIENT_IMPLEMENTATION_REPORT.md с точными статусами.

## Критерии готовности

- Постоянная визуальная структура находится в Unity-сценах и редактируемых префабах.
- Обучение и локальный матч с ботом работают без сервера.
- Онлайн-поведение и внешние контракты остаются без изменений.
- Основные сцены и ссылки проверены в редакторе, доступные локальные сценарии испытаны, сборка проверена либо ограничение задокументировано.
- Все отчёты отражают только действительно выполненную работу.
